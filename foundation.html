AI working-system design — foundation

Agreed 13 Nov 2026 between Admin and agent12. Clean-sheet design; nothing existing shapes it. This page must survive every session, model and device.

Purpose (step 0, open for Admin's final word): the system makes Admin's accumulated understanding — problems, decisions, corrections, tools — outlive any session, any model and any single machine, while staying small enough to be read by Admin or a model in a minute.

The ten essences (the shape)

  1. Problem class over instance — strip any problem to its solution-free trunk; one solved trunk pre-solves future leaves. Ask with: "restate the problem solution-free" / "problem class, not my instance".
  2. Work has no clean edges — engineering is one continuous, entangled story; capture happens when understanding changes, because "the end" never comes.
  3. The model is stateless and probabilistic — it reasons per call, retains nothing, misses things; whatever must persist lives in files, never in a session.
  4. Sessions are perishable containers — quality accumulating inside long-lived sessions dies with them; sessions must be disposable, interchangeable processors over durable files.
  5. Attention is bought with tokens — force-feed only the few must-not-miss lines; everything else behind pointers, or the cure becomes the noise.
  6. The collaboration cost sits with Admin — making models understand, decoding answers, re-teaching every session; the system exists to push that cost down permanently.
  7. Not everything is a rule — the tacit layer cannot be legislated and dies with the session (a fundamental limit); whole worked exchanges transmit disposition better than rules, so keep a few of them as artifacts.
  8. Delivery is a dialogue loop — shared facts first, one checkable bite, inspect together, then the next; never a dumped plate; never prescribe a file edit without quoting what is there (before/after).
  9. Quick, tangible wins now — if it can be done today, it is done today; "with time" is the exception, not the rhythm.
  10. Clean sheet — design from these truths; what already exists is judged against the design afterwards (keep, migrate, discard), never bent into it.
  11. Rules collide and gaps get filled silently — directives written in one context (at the desk) keep applying in others (away from it), and where no rule speaks, the model fills the silence with the convenient assumption; the system must let collisions be seen and make the model surface an unstated gap instead of assuming through it. (Added 13 Nov: live case — "hand over full file paths" rules collided with Admin not being at the machine.)
